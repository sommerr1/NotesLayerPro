# 📘 Техническое задание

## Chrome Extension: Inline Notes & AI Clarification MVP

### (Аннотации + мини‑диалоги с ИИ прямо на страницах Copilot/LLM/веб‑сайтов)

---

# 1. Цель проекта

Создать расширение Chrome, позволяющее пользователю:

- оставлять **аннотации/заметки** на словах и фразах в интерфейсах Copilot, LLM‑чатах и любых веб‑страницах;
- быстро **прояснять вопросы через ИИ** (Gemini в Google Search) прямо внутри заметки;
- переключаться между режимами **Annotation ↔ Question**;
- хранить заметки локально (IndexedDB);
- искать заметки локально и глобально;
- восстанавливать заметки даже при изменении DOM или текста.

MVP должен быть функциональным, устойчивым и расширяемым.  
Дизайн — минимальный, без сложных UI‑решений.

---

# 2. Архитектура расширения

## 2.1. Компоненты

### **Content Script**

- внедряется на все страницы;
- отслеживает выделение текста;
- создаёт подсветку и маркеры заметок;
- отображает карточку заметки (popup);
- восстанавливает заметки при загрузке страницы;
- взаимодействует с IndexedDB через background.

### **Background Service Worker**

- управляет IndexedDB;
- выполняет запросы к Google Search (через скрытую вкладку);
- обеспечивает message passing между popup/content/options.

### **IndexedDB**

Хранит:

- страницы;
- заметки;
- якоря;
- мини‑диалоги;
- индексы для поиска.

### **Popup UI**

- глобальный поиск;
- список страниц;
- список заметок по странице.

### **Options Page**

- настройки (в будущем);
- выбор LLM‑провайдера (в будущем).

# 3. Модель данных

## 3.1. Note (заметка)

```
{
  id: string,
  pageId: string,
  anchorId: string,
  type: "annotation" | "question",
  annotationContent: RichTextJSON,
  questionContent?: string,
  aiAnswer?: string,
  warningLevel: "none" | "yellow" | "red",
  createdAt: number,
  updatedAt: number
}
```

## 3.2. Anchor (якорь)

```
{
  id: string,
  pageId: string,
  text: string,
  contextLeft: string,
  contextRight: string,
  domPath: string,
  coords: { xPercent: number, yPercent: number },
  createdAt: number
}
```

## 3.3. Page

```
{
  id: string,
  url: string,
  title: string,
  createdAt: number,
  updatedAt: number
}
```

# 4. Алгоритм якорения (Anchoring Strategy)

## 4.1. При создании заметки

Сохраняем:

- выделенный текст;
- контекст слева/справа (30–50 символов);
- DOM‑путь (CSS selector + index);
- относительные координаты внутри контейнера.

## 4.2. При восстановлении заметки

Порядок:

### **1. Text match (primary)**

- точное совпадение текста;
- если нет → fuzzy match по тексту + контексту;
- если fuzzy match → warningLevel = "yellow".

### **2. DOM match (secondary)**

- если текст не найден → ищем DOM‑элемент по пути;
- если найден → warningLevel = "red".

### **3. Coordinates (fallback)**

- если DOM не найден → позиционируем по coords;
- warningLevel = "red".

## 4.3. Поведение при предупреждениях

Если warningLevel ≠ "none":

- заметка отображается с красной/жёлтой рамкой;
- показывается иконка ⚠️;
- пользователь может:
    - перевесить заметку на новый текст;
    - удалить заметку;
    - оставить как есть.

# 5. UI/UX MVP

## 5.1. Подсветка текста

- выделенный фрагмент получает background‑color;
- рядом появляется маленькая иконка заметки.

## 5.2. Карточка заметки (popup)

Открывается при клике на маркер.

Содержит:

- rich‑text редактор аннотации;
- кнопку “Задать вопрос”;
- если есть вопрос:
    - поле вопроса;
    - ответ ИИ;
    - кнопка “Принять как аннотацию”;
    - кнопка “Удалить вопрос”.

## 5.3. Режимы заметки

### **Annotation mode**

- обычная заметка;
- rich‑text.

### **Question mode**

- поле вопроса;
- кнопка “Получить ответ”;
- ответ ИИ;
- возможность редактировать ответ;
- кнопка “Схлопнуть в аннотацию”.

Переходы:

- Annotation → Question (по кнопке);
- Question → Annotation (по кнопке).

# 6. Мини‑диалог с ИИ (Gemini через Google Search)

## 6.1. Процесс

1. Пользователь вводит вопрос.
2. Background открывает скрытую вкладку Google Search.
3. Формирует запрос:  
    **“Кратко и понятно объясни: [вопрос]”**
4. Получает ответ Gemini/AI‑блока.
5. Возвращает текст в заметку.

## 6.2. Требования

- архитектура должна позволять заменить источник ИИ в будущем;
- создать абстракцию `LLMProvider`.

# 9. Основные сценарии (User Flows)

## 9.1. Создание заметки

1. Пользователь выделяет текст.
2. Появляется мини‑кнопка “Создать заметку”.
3. Создаётся заметка + якорь.
4. Текст подсвечивается.
5. Открывается карточка заметки.

## 9.2. Задать вопрос ИИ

1. В карточке нажать “Задать вопрос”.
2. Ввести вопрос.
3. Получить ответ.
4. При необходимости:
    - отредактировать,
    - схлопнуть в аннотацию.

## 9.3. Восстановление заметок при загрузке страницы

1. Content script получает список заметок по URL.
2. Для каждой:
    - пытается восстановить текстовый якорь;
    - если не получилось → DOM;
    - если не получилось → coords.
3. Отображает подсветку и маркеры.

## 9.4. Перевешивание заметки

1. Пользователь нажимает “Привязать заново”.
2. Выделяет новый текст.
3. Якорь обновляется.

- код должен быть модульным и расширяемым.
